# Proposal

## Why

当前使用方式是「双击 start.bat → 浏览器打开 127.0.0.1:5210」，对工具型产品而言存在摩擦：需要保留浏览器标签页、服务生命周期与命令行窗口绑定、无系统级入口（托盘/开机自启/原生通知）。用户提出后续拓展为桌面应用端，让本工具像原生应用一样：桌面图标启动、托盘常驻、任务完成系统通知、可选开机自启。

拓展基础已具备：`server/src/core/` 与 HTTP 层解耦（add-worktree-manager design 的既定意图——"可复用给未来桌面端/Agent"），前端为纯静态构建产物（`web/dist`），持久化与数据目录逻辑独立成模块（`data-root-resolver`），均可被桌面壳直接复用。

## What Changes

- 新增桌面壳层（技术选型在 design 阶段定夺，候选 Electron / Tauri）：
  - 评估维度：安装包体积、内存占用、对 WebView2 运行时的依赖、与现有 Koa 服务（SSE 日志流、静态托管）的兼容性
  - 承载方式两阶段：一期内嵌启动现有 Koa 服务并加载 `web/dist`（最小改动、浏览器访问模式保留）；二期评估 core 层直连去 HTTP 化
- 系统能力：系统托盘（服务状态、快速打开主界面、退出）、任务完成原生通知、关闭行为可选（最小化到托盘 / 直接退出）、开机自启（默认关闭，设置页可开）
- 端口策略：5210 被占用时的自动换端口与提示（当前仅报错）
- 打包分发：Windows 安装包优先（NSIS/MSI），应用图标；自动更新方案评估（二期）
- 平台范围：一期仅 Windows（与现有系统支持范围一致）；macOS/Linux 的路径与 junction 适配作为前置独立任务另行评估

## Capabilities

### New Capabilities

- `desktop-app`: 桌面应用壳——窗口与托盘生命周期、内嵌服务承载、端口冲突处理、原生通知、开机自启、Windows 打包分发

### Modified Capabilities

- `worktree-console`: 设置页新增桌面相关开关（开机自启、关闭行为）；浏览器访问模式保留为并行使用方式

## Impact

- 代码：新增桌面壳目录（如 `desktop/`，含主进程、托盘、打包配置）；`server` 保持可独立运行（`npm start` 与浏览器访问不废除）；设置存储新增桌面偏好字段（沿用 settings.json，与数据目录分离）
- 依赖：新增桌面壳框架依赖（仅桌面端，不进入 server 运行时依赖）
- 交付物：Windows 安装包；现有源码运行方式不受影响
- 风险：SSE 在壳内 WebView 的兼容性需在 design 阶段原型验证；嵌入式存储（nedb）无跨进程锁——桌面端需确保同一时刻仅一个服务实例（单实例锁）
