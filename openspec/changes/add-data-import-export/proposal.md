# Proposal

## Why

本工具的业务数据（任务记录与安装日志、worktree 创建历史、需求任务、最近主仓库）全部积累在本机数据根目录（nedb 三库 + JSONL 日志），当前没有任何导入导出能力：换电脑、重装系统前备份、把数据分享给同事起步，都只能手动停服务后按目录结构拷贝 `nedb/` 与 `job-logs/`，门槛高且容易漏拷或拷错版本。需要一键导入导出，把数据当作可携带资产。

## What Changes

- **一键导出**：新增导出接口，把业务数据聚合为单个归档文件（JSON 格式，扩展名 `.wtm-data.json`），浏览器直接下载；内容含元信息（格式版本 `formatVersion`、导出时间、各表条数）与四类业务数据：任务元数据、创建历史、需求任务、最近主仓库；安装任务日志体积大，默认不含，可勾选包含
- **一键导入**：设置页选择归档文件 → 前端解析展示概览（各表条数、导出时间、格式版本）→ 用户选择导入策略后执行：
  - 合并去重（默认）：按记录 id 去重合并，同 id 冲突时保留本地较新（比较 `updatedAt` / `finishedAt`）
  - 覆盖当前数据：需显式勾选确认；执行前自动备份当前数据到数据目录 `backup/<时间戳>/`，失败可手动还原
- **校验与安全**：格式/版本校验（不识别或高版本归档给出明确提示，拒绝静默导入）；导入在服务内完成保证一致性，导入完成后前端自动刷新各列表；配置文件 `settings.json` 属机器相关路径，不参与导入导出
- **入口**：设置页新增「数据管理」区（导出下载、导入选择与策略、结果反馈）

## Capabilities

### New Capabilities

- `data-import-export`: 数据一键导出与导入——归档格式与版本、导出聚合、导入策略（合并/覆盖）、导入前自动备份、格式校验与错误提示

### Modified Capabilities

- `local-persistence`: 暴露全量读取与批量写入能力供导入导出使用（不改既有存取行为）
- `worktree-console`: 设置页新增「数据管理」区块

## Impact

- 代码：server 新增 data-transfer 模块（导出聚合、归档校验、导入策略、自动备份）+ 两个路由；web 设置页新增区块（沿用 usePendingActions 的 loading 约定）
- 数据：导入「覆盖」模式会在数据目录产生 `backup/<时间戳>/` 备份目录（需在设置页说明，避免用户疑惑）
- 兼容：归档格式带 `formatVersion`，未来结构变更按版本升级导入逻辑；导出不依赖操作系统路径（记录内的绝对路径跨机器可能失效，导入时原样保留并在结果中提示核对）
- 不影响：运行中任务、浏览器/未来桌面端使用方式
